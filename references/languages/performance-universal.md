# 通用性能检查清单（Performance — Language Agnostic）

> 性能审查关注点和检测指标

## 1. 数据库查询

### N+1 查询
- [ ] 批量查询是否使用了 `JOIN` 或 `IN` 替代循环查询
- [ ] ORM 是否启用了 eager loading
- [ ] 是否存在循环中的单次查询

```
# ❌ N+1
for user in users:
    orders = db.query("SELECT * FROM orders WHERE user_id = ?", user.id)

# ✅ 批量查询
user_ids = [u.id for u in users]
orders = db.query("SELECT * FROM orders WHERE user_id IN ?", user_ids)
```

### 索引使用
- [ ] 查询字段是否有索引
- [ ] 是否避免了全表扫描
- [ ] 复杂查询是否查看了执行计划

## 2. 算法复杂度

- [ ] 是否存在 O(n²) 或更差的嵌套循环
- [ ] 大数据处理是否使用了合适的算法
- [ ] 是否使用了缓存避免重复计算

| 场景 | 推荐复杂度 | 反模式 |
|------|-----------|--------|
| 查找 | O(1) hash / O(log n) BST | O(n) 线性扫描 |
| 排序 | O(n log n) | O(n²) 冒泡/选择排序 |
| 去重 | O(n) set | O(n²) 双重循环 |

## 3. 内存管理

### 泄漏检测
- [ ] 是否有未释放的资源连接
- [ ] 大对象是否及时释放
- [ ] 缓存是否有大小限制和淘汰策略

### 最佳实践
- [ ] 流式处理大文件而非一次性加载
- [ ] 避免创建不必要的对象拷贝
- [ ] 使用生成器/迭代器处理大数据流

```python
# ❌ 坏：一次性加载全部数据
data = load_all_data()  # 可能 GB 级

# ✅ 好：流式处理
for batch in load_data_in_batches():
    process(batch)
```

## 4. 缓存策略

| 层级 | 适用场景 |  TTL 建议 |
|------|---------|----------|
| 应用内缓存 | 频繁读取的热点数据 | 秒级 |
| 分布式缓存 | 跨实例共享 | 分钟级 |
| CDN | 静态资源 | 小时/天级 |
| 数据库查询缓存 | 复杂聚合查询 | 分钟级 |

检查项：
- [ ] 缓存 key 是否包含足够的区分信息
- [ ] 缓存击穿/穿透/雪崩是否有防护
- [ ] 缓存一致性策略是否明确

## 5. 并发与异步

- [ ] I/O 密集型操作是否使用了异步
- [ ] 长耗时操作是否放入了后台任务
- [ ] 是否有合理的并发度控制（避免线程池耗尽）

## 6. 网络优化

- [ ] 是否减少了不必要的网络往返
- [ ] 大响应是否使用了分页
- [ ] 是否启用了压缩（gzip/brotli）
- [ ] GraphQL 是否避免了 over-fetching

## 7. 性能审查检查清单

- [ ] 有无明显的 O(n²) 算法
- [ ] 有无 N+1 查询模式
- [ ] 有无未设置超时的外部调用
- [ ] 有无在热路径上创建大对象
- [ ] 有无未限制大小的缓存
- [ ] 有无同步阻塞 I/O
- [ ] 有无重复计算相同结果
- [ ] 响应体是否过大（考虑压缩/分页）

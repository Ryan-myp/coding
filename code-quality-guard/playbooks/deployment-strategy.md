# 部署策略 Playbook

## 触发条件

- 制定发布计划
- 选择部署方式
- 设计灰度发布
- 规划回滚方案

## 部署策略对比

| 策略 | 风险 | 复杂度 | 适用场景 | 回滚速度 |
|------|------|--------|---------|---------|
| **Batch** | 🔴 高 | 🟢 低 | 内部工具 | 慢（全量） |
| **Canary** | 🟡 中 | 🟡 中 | 新功能验证 | 快（切回） |
| **Blue-Green** | 🟢 低 | 🟡 中 | 重大变更 | 极快（切换） |
| **Feature Flag** | 🟢 最低 | 🟡 中 | 功能渐进 | 即时（关 flag） |
| **Rolling** | 🟡 中 | 🟢 低 | 常规发布 | 中（逐个） |

## 策略 1: Feature Flags（特性开关）

```python
# 代码中嵌入开关
def process_payment(amount: float, user: User) -> PaymentResult:
    if use_v2_gateway():  # 特性开关
        return new_gateway_charge(amount, user)
    return legacy_gateway_charge(amount, user)

# 开关配置
FEATURE_FLAGS = {
    "use_v2_gateway": {
        "default": False,
        "rollout": 0.0,     # 0% → 10% → 50% → 100%
        "target_users": ["beta_group"],
    }
}
```

**最佳实践：**
- 开关命名清晰：`use_<feature_name>`
- 设置过期时间，定期清理
- 不同环境独立配置
- 关键开关需要审批

## 策略 2: Canary 发布

```
              1%       10%       50%      100%
    ┌────┬────┼────┬────┼────┬────┼────┬────┐
    │Blue│C1  │C10 │C50 │Blue│
    │100%│ 1% │10% │50% │ 50%│
    └────┴────┴────┴────┴────┴────┘
         逐步放量，监控指标
```

**Canary 检查项：**
- [ ] 错误率无显著升高
- [ ] 延迟 p99 无显著增加
- [ ] 业务指标（转化率等）正常
- [ ] 资源使用正常（CPU/内存）
- [ ] 无新增告警

## 策略 3: Blue-Green 部署

```
环境A (Blue)  ──▶ 生产流量
环境B (Green) ──▶ 部署新版本

                    切换流量
                         │
                         ▼
环境A (Blue)  ──▶ 新版本运行
环境B (Green) ──▶ 旧版本备份（可快速回切）
```

**切换决策点：**
```
新版本部署完成
    │
    ▼
健康检查通过？──No──▶ 告警，不回切（保留旧版）
    │Yes
    ▼
冒烟测试通过？──No──▶ 回切到旧版本
    │Yes
    ▼
切流量 → 监控 30min → 确认无误 → 下线旧版本
```

## 策略 4: Rolling 滚动发布

```
Pod1 Pod2 Pod3 Pod4 Pod5
 │    │    │    │    │
 ▼    │    │    │    │  逐个更新
─▼───▼───▼───▼───▼─
新   新   新   新   旧   逐步替换
```

**参数：**
- `maxSurge`: 最多额外创建的 Pod 数（如 25%）
- `maxUnavailable`: 最多不可用的 Pod 数（如 25%）

## 部署前检查清单

```
□ 所有测试通过
□ 代码审查通过
□ 配置已审核（环境变量、密钥）
□ 数据库迁移脚本已验证
□ 回滚方案已准备
□ 监控告警已配置
□ Runbook 已更新
□ 相关团队已通知
□ Feature flags 已检查
□ 依赖服务版本兼容
□ 备份已完成（如需要）
```

## 部署后检查清单

```
□ 健康检查通过
□ 错误率正常（对比基线）
□ 延迟正常（p50/p95/p99）
□ 业务指标正常
□ 日志无异常
□ 告警无新增
□ 监控面板正常
□ 关键用户路径验证通过
```

## 回滚决策树

```
部署后异常
    │
    ├─▶ P0（服务不可用）→ 立即回滚
    │
    ├─▶ P1（严重功能损坏）→ 评估影响 → 回滚或热修复
    │
    ├─▶ P2（部分功能异常）→ 关闭特性开关 → 监控
    │
    └─▶ P3（轻微问题）→ 记录 → 下个版本修复
```

## 发布频率建议

| 场景 | 发布频率 | 策略 |
|------|---------|------|
| 高频迭代（互联网产品） | 每日/每周 | Feature Flag + Canary |
| 中频迭代（企业软件） | 每周/每两周 | Rolling + Code Review |
| 低频迭代（金融/医疗） | 每月/季度 | Blue-Green + 严格审批 |

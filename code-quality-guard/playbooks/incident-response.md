# 事故响应 Playbook

## 触发条件

- 线上服务故障
- 严重 bug 影响用户
- 安全事件
- 数据丢失或损坏

## 事故分级

| 级别 | 定义 | 响应时间 | 通知范围 |
|------|------|---------|---------|
| **P0/Critical** | 服务完全不可用，数据丢失 | 5 min | 全员 + 管理层 |
| **P1/High** | 核心功能严重受损 | 15 min | 团队 + 相关方 |
| **P2/Medium** | 部分功能异常，有 workaround | 1 hour | 团队内 |
| **P3/Low** | 轻微问题，不影响主流程 | 24 hour | 按需 |

## 响应流程

### Phase 1: 发现与确认（0-5 min）

```
1. 收到告警/报告
2. 确认影响范围
3. 确定事故级别
4. 启动响应
```

**确认清单：**
- [ ] 哪个服务/功能受影响？
- [ ] 影响多少用户？
- [ ] 是否有数据损失？
- [ ] 是否安全事件？

### Phase 2: 遏制与恢复（5-30 min）

**优先级：恢复服务 > 根因分析**

```
1. 止血 — 阻止影响扩大
   - 回滚最近变更
   - 关闭特性开关
   - 限流/熔断
   - 切换备用服务

2. 恢复 — 尽快恢复服务
   - 重启服务
   - 切换到备份
   - 手动修复数据
```

**常用止血手段：**

| 问题类型 | 止血手段 |
|---------|---------|
| 代码 bug | 回滚到上一版本 |
| 配置错误 | 回滚配置 |
| 流量激增 | 限流/降级 |
| 数据库问题 | 切换从库/重启连接池 |
| 第三方故障 | 熔断/降级到缓存 |
| 安全攻击 | 封禁 IP/断网 |

### Phase 3: 调查与修复（30 min - 数小时）

```
1. 收集证据
   - 日志（事故发生前后）
   - Metrics（变化趋势）
   - 变更历史（最近部署）
   - 用户报告

2. 定位根因
   - 5 Whys 分析
   - 时间线重建
   - 假设验证

3. 实施修复
   - 热修复（hotfix）
   - 验证修复有效
   - 灰度发布
```

### Phase 4: 恢复验证

```
1. 服务健康检查
2. 数据一致性校验
3. 关键用户路径测试
4. 监控指标恢复正常
5. 通知相关人员恢复
```

### Phase 5: 事后复盘（Post-mortem）

**无责备文化** — 复盘目标是改进系统，不是追究责任。

```markdown
# Post-mortem: [事故标题]

## 概要
- **时间**: YYYY-MM-DD HH:MM - HH:MM
- **级别**: P1
- **影响**: 服务 X 不可用 N 分钟，影响 Y% 用户
- **根因**: [一句话描述]

## 时间线
| 时间 | 事件 |
|------|------|
| HH:MM | 告警触发 |
| HH:MM | 确认事故 |
| HH:MM | 开始止血 |
| HH:MM | 服务恢复 |
| HH:MM | 根本原因确认 |

## 根因分析（5 Whys）
1. 为什么服务不可用？→ 数据库连接池耗尽
2. 为什么连接池耗尽？→ 某查询未加索引，全表扫描占用连接
3. 为什么没有索引？→ 上线时漏加
4. 为什么没发现？→ Code Review 未检查 DDL
5. 为什么没检查？→ Review checklist 缺少 DB 相关项

## 改进措施
| 措施 | 负责人 | 截止日期 | 状态 |
|------|--------|---------|------|
| 更新 Code Review checklist | @alice | 2025-09-15 | ✅ |
| 添加 DDL 自动检查 | @bob | 2025-09-20 | 🟡 |
| 连接池监控告警 | @carol | 2025-09-18 | ✅ |

## 经验教训
- [ ] 部署前应检查索引
- [ ] 连接池应有预警阈值
- [ ] 慢查询应有自动熔断
```

## 沟通模板

### 内部通报
```
🚨 [P1] 支付服务异常

影响：支付接口超时，约 30% 请求失败
开始时间：2025-09-10 14:30
当前状态：已定位，正在修复
预计恢复：15:00
跟进频道：#incident-payment-20250910
```

### 对外公告
```
尊敬的客户，我们注意到支付服务出现短暂异常。
技术团队已快速定位并正在修复，预计 15:00 前恢复。
对此给您带来的不便，我们深表歉意。
```

## 检查清单

### 事故前（预防）
- [ ] 监控告警已配置
- [ ] Runbook 已更新
- [ ] 回滚方案已准备
- [ ] 值班表已排定
- [ ] 沟通渠道已建立

### 事故中
- [ ] 指定 incident commander
- [ ] 记录时间线
- [ ] 内外部沟通及时
- [ ] 止血措施已执行
- [ ] 根因分析进行中

### 事故后
- [ ] Post-mortem 已完成
- [ ] 改进措施已列出
- [ ] 措施已分配负责人
- [ ] 经验教训已文档化
- [ ] 监控告警已优化

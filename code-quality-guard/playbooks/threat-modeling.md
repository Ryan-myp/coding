# STRIDE 威胁建模 Playbook

## 触发条件

- 设计新 API/接口
- 处理用户输入
- 管理认证/授权
- 存储或传输敏感数据
- 集成外部服务
- 处理支付或 PII 数据

## 五步威胁建模流程

### Step 1: 绘制数据流图（DFD）

```
┌─────────┐     ┌─────────┐     ┌─────────┐
│  Client  │────▶│  API    │────▶│ Database│
│ (User)   │     │ Gateway │     │  (Store)│
└─────────┘     └─────────┘     └─────────┘
      │               │                │
      ▼               ▼                ▼
  [信任边界]      [信任边界]      [信任边界]
```

**识别信任边界：**
- 外部输入进入系统的点（HTTP、消息队列、文件上传）
- 特权操作执行的点（admin API、数据库写入）
- 敏感数据存取的点（密钥、PII）

### Step 2: 识别资产

| 资产类型 | 示例 | 保护级别 |
|---------|------|---------|
| 凭证 | 密码、API Key、JWT | 🔴 最高 |
| PII | 邮箱、电话、地址 | 🔴 高 |
| 支付数据 | 卡号、账单信息 | 🔴 最高 |
| 业务数据 | 订单、库存 | 🟡 中 |
| 日志 | 访问日志、错误日志 | 🟢 低 |

### Step 3: STRIDE 分析

对每个信任边界，逐项检查：

| 威胁 | 问题 | 典型攻击 | 缓解措施 |
|------|------|---------|---------|
| **S**poofing | 谁能伪装成合法实体？ | 伪造 token、中间人 | 强认证、证书固定 |
| **T**ampering | 数据能否被篡改？ | SQL注入、MITM | 参数化查询、TLS |
| **R**epudiation | 操作能否抵赖？ | 否认发送消息 | 审计日志、数字签名 |
| **I**nformation Disclosure | 数据是否泄露？ | 信息泄露、暴力破解 | 加密、最小化输出 |
| **D**enial of Service | 能否被淹没？ | DDoS、资源耗尽 | 限流、熔断、超时 |
| **E**levation of Privilege | 能否越权？ | IDOR、权限提升 | RBAC、所有权校验 |

### Step 4: 编写滥用用例

对每个功能，写"如果我要滥用它会怎样"：

```
功能：创建订单

正常用例：
- 用户提交有效订单 → 创建成功

滥用用例：
- 用户提交空订单 → 应返回 400
- 用户提交负数金额 → 应拒绝
- 用户修改他人订单 ID → 应返回 403
- 用户并发提交相同订单 → 应幂等处理
- 用户在订单中注入脚本 → 应转义输出
```

### Step 5: 输出威胁报告

```markdown
# 威胁模型：[功能名称]

## 信任边界
1. HTTP 入口 → API Gateway
2. API Gateway → 数据库
3. 外部支付服务回调

## 识别的威胁
| # | STRIDE | 威胁描述 | 严重程度 | 缓解措施 | 状态 |
|---|--------|---------|---------|---------|------|
| 1 | Tampering | SQL注入风险 | 🔴 High | 参数化查询 | ✅ 已缓解 |
| 2 | Spoofing | JWT伪造 | 🟡 Medium | 签名验证+过期检查 | 🟡 待实现 |
```

## 常用威胁检测模式

```python
# Spoofing 检测
- 是否有未经验证的 token/session？
- 是否有硬编码的凭据？
- 是否有不安全的跨域配置？

# Tampering 检测
- 是否有字符串拼接的 SQL？
- 是否有未 sanitization 的用户输入？
- 是否有不安全的反序列化？

# Repudiation 检测
- 关键操作是否有审计日志？
- 日志是否防篡改？

# Information Disclosure 检测
- 是否有敏感信息在日志中？
- API 响应是否包含多余字段？
- 错误信息是否泄露内部细节？

# DoS 检测
- 是否有无限制的循环/递归？
- 外部调用是否有超时？
- 是否有内存泄漏风险？

# Elevation 检测
- 资源操作前是否检查了所有权？
- 是否有未校验的权限？
- 管理接口是否有额外保护？
```
